# 第一章：初识智能体

## 一句话定义

智能体（Agent）是在环境中持续获取观察、基于目标自主决策，并通过执行器改变环境状态的系统。最小闭环是：

```text
Observation（观察） → Thought/Planning（思考与规划） → Action（行动）
       ↑                                                   ↓
       └────────────── Environment（环境反馈） ────────────┘
```

LLM Agent 的变化在于：大语言模型承担通用决策与语言理解，工具、API 或代码执行器承担真实世界的行动。

## 传统智能体的能力阶梯

| 类型 | 决策依据 | 优势 | 局限 |
| --- | --- | --- | --- |
| 简单反射 | 当前输入与规则 | 快、稳定 | 没有记忆，无法处理上下文 |
| 基于模型的反射 | 当前输入 + 内部世界模型 | 能维护状态 | 世界模型构建成本高 |
| 基于目标 | 目标与规划 | 能考虑未来 | 规划耗时，目标通常单一 |
| 基于效用 | 效用函数与多目标权衡 | 能处理冲突目标 | 效用建模困难 |
| 学习型 | 经验、反馈与奖励 | 能持续改进 | 训练成本、探索风险高 |

现代 LLM Agent 通常是混合式系统：模型负责规划，工具调用负责即时行动，下一轮观察再修正计划。

## 任务环境：PEAS

设计 Agent 前先写清 PEAS：Performance（性能指标）、Environment（环境）、Actuators（执行器）、Sensors（传感器）。以旅行助手为例：

- 性能：信息准确、预算符合、行程可执行、响应及时。
- 环境：天气、地图、航班、酒店和用户偏好等动态信息。
- 执行器：搜索 API、天气 API、预订接口、消息发送器。
- 传感器：用户输入、API 返回值、历史对话和外部事件。

现实任务通常是部分可观察、随机、动态、序贯，并可能包含其他行动者。因此 Agent 需要记忆、重试、校验和停止条件。

## 交互协议

一个可工程化的最小协议是 `Thought → Action → Observation`：模型输出下一步工具及参数；解析器执行工具；工具结果被整理成 Observation 重新交给模型。协议必须约束格式，并处理解析失败、未知工具、超时和最大循环次数。

## 本章代码对应

[`chapter1/demo1.py`](chapter1/demo1.py) 实现了一个天气与景点推荐 Agent：

1. `AGENT_SYSTEM_PROMPT` 定义工具、输出格式和结束动作。
2. `available_tools` 将函数名映射到 Python 函数。
3. `prompt_history` 保存用户请求、模型输出和 Observation。
4. 主循环调用兼容 OpenAI API 的模型，解析 `Action`，执行工具，再把结果写回上下文。
5. `Finish[...]` 是显式停止条件，循环上限避免模型无限调用工具。

工程改进建议：对模型输出使用更严格的结构化函数调用；为工具参数做 schema 校验；为外部请求增加超时、重试与日志；对天气和搜索结果标注时间与来源。

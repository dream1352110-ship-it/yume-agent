# 第二章：智能体发展史

## 主线：每一代范式都在解决上一代的痛点

Agent 的历史不是技术名词的堆叠，而是一条问题驱动的演化链：

```text
符号与规则 → 专家系统 → 连接主义/神经网络 → 强化学习 → LLM 驱动 Agent
```

每次能力跃迁也会带来新的局限：规则系统难以覆盖常识，神经网络难解释，强化学习样本和奖励昂贵，LLM 则面临幻觉、成本、延迟和安全问题。

## 符号主义与专家系统

物理符号系统假说把智能看作符号的表示与逻辑操作。专家系统将领域知识写入知识库，由推理机执行规则：

- 正向链：从已知事实出发，不断触发规则，属于数据驱动。
- 反向链：从目标反推所需条件，属于目标驱动。
- 置信因子：用数值表达不确定结论，而不是只返回真/假。

SHRDLU 通过“积木世界”展示了语言理解、规划、记忆和行动的组合，但也暴露出微观世界成功不代表开放世界通用。符号主义的关键瓶颈是知识获取、常识表示、框架问题和系统脆弱性。

## 连接主义、学习与强化学习

连接主义把知识隐式编码在神经网络参数中，擅长从数据中学习模式，泛化到未见过的输入；代价是解释性弱、需要大量数据，且可能产生不可靠输出。

强化学习把 Agent 放进环境，通过状态、动作、奖励和策略的交互优化长期回报。它适合序贯决策，但奖励设计、探索安全、样本效率和训练成本都是工程难点。

## LLM Agent 的位置

LLM Agent 不是“只换了一个更大的模型”，而是把语言模型放入一个可行动的系统：

- 模型提供自然语言理解、任务分解和候选行动。
- 工具提供搜索、计算、数据库和执行能力。
- 记忆保存跨轮次信息。
- 编排器负责循环、权限、重试、评估和停止。

因此，LLM Agent 更接近神经符号混合系统：神经网络负责模式识别与生成，结构化消息、计划和工具调用承担符号化的可执行接口。

## 本章代码对应

[`chapter2/demo.py`](chapter2/demo.py) 是一个规则驱动的 ELIZA 风格对话程序。它用正则表达式匹配输入，用模板生成回答，再做简单的人称代词转换。这个例子适合对照理解：

- 规则和模板就是显式知识库。
- 匹配器就是简化的推理机。
- 程序没有世界模型、长期目标和学习能力，因此不是现代意义上的自主 Agent。
- 它的可解释性强、行为稳定，但覆盖范围受规则数量限制。

## 设计启示

1. 先定义环境、目标和反馈，再决定使用规则、模型还是混合架构。
2. 能用确定性规则解决的安全边界，不要全部交给 LLM。
3. 对开放任务采用“模型提出计划 + 程序验证与执行”的分工。
4. 把历史范式的失败模式转化为测试项：知识缺失、状态漂移、奖励投机、幻觉和权限越界。
